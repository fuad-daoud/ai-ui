# ai-ui v0.4: menu, sheet, theme picker, ui.js

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Do the steps in order.

**Precondition (STOP if unmet):** `git log --oneline -3` shows `docs: plan ai-ui v0.4` at the top, and `git status --short` is empty.

**Goal:** the library gains a menu (a popover anchored to its opener), a sheet (a modal `<dialog>` docked to an edge), a theme picker (swatches whose faces preview any palette and mode), and `ui.js` for their keys; palettes and modes apply on any element; `theme.js` marks the current choice and says when it changes. Docs, the site and the version (0.4.0) follow.

**Architecture:** CSS for three new components and a token selector change; one new script (`js/ui.js`), embedded and served like `theme.js`; React components for each (Go writes their markup from `DESIGN.md`, pinned by parity goldens); gallery and fixture markup; browser, unit and parity tests.

**Tech Stack:** CSS layers, popover and anchor positioning, `<dialog>`, plain JS, React 19, Go `embed`, Vitest with jsdom, Playwright with axe, the Go site generator.

**Spec:** `docs/superpowers/specs/2026-11-12-v0.4-overlays-and-theme-design.md`. Read it first.

## Review Focus

1. **Palettes on any element.** Blue's colours sit on `:root, [data-palette="blue"]` and mono's on `[data-palette="mono"]`, after it, so `<html data-palette="mono">` still takes mono (same specificity, later rule). Pinned by the gallery's mono pages and `a face paints its own palette and mode inside another`. `tokens_test.go` parses the new selectors; its contrast pairs must still cover blue and mono.
2. **The menu works without `ui.js`.** Opening, light dismiss, Escape and the anchor are the browser's. Pinned by `still opens and closes without ui.js`. `ui.js` only adds keys, focus and a placement fallback.
3. **Tab and activation close the menu; a radio doesn't.** Pinned by `Tab closes it and moves on from the opener` and `a radio item is checked by theme.js, focused on open, and keeps the menu open`.
4. **Sheet motion.** Only a modal sheet (`:modal`) slides in, so one drawn in place stays still: the density test compares computed styles and would see a running transition. Pinned by `slides in, unless reduced motion is asked for` and `compact has no effect without the attribute`.
5. **Pressed marks.** `theme.js` writes `aria-checked` for radio roles and `aria-pressed` otherwise, after `DOMContentLoaded` and every change. Pinned by the vitest cases and the picker's browser test.
6. **The site keeps its rules.** Every component is in the home pile and demoed on Components; nothing in the pile is covered at any tested width; Tab reaches every pile control. A closed menu's controls aren't tab stops, which is why the Components Tab test now skips `[popover]` as it skips `dialog`.

import { useEffect, type ComponentPropsWithRef } from "react";
import { cx } from "./util";

export type SwatchesProps = Omit<ComponentPropsWithRef<"div">, "role"> & { label: string };

// Swatches is a row of theme choices.
export function Swatches({ label, className, ...rest }: SwatchesProps) {
  return <div {...rest} className={cx("ui-swatches", className)} role="group" aria-label={label} />;
}

export type SwatchTheme = "light" | "dark" | "system";

export type SwatchProps = Omit<ComponentPropsWithRef<"button">, "children" | "type"> & {
  theme: SwatchTheme;
  palette: string;
  label: string;
};

type ThemeWindow = { aiui?: { theme?: { sync?: () => void } } };

// Swatch is a button that picks a theme and palette through theme.js, which
// also marks the current one aria-pressed. Its face previews the choice.
export function Swatch({ theme, palette, label, className, ...rest }: SwatchProps) {
  useEffect(() => {
    (window as unknown as ThemeWindow).aiui?.theme?.sync?.();
  }, [theme, palette]);
  return (
    <button {...rest} className={cx("ui-swatch", className)} type="button" data-ui-set-theme={theme} data-ui-set-palette={palette} aria-label={label}>
      <SwatchFace theme={theme} palette={palette} />
    </button>
  );
}

export type SwatchFaceProps = Omit<ComponentPropsWithRef<"span">, "children"> & { theme: SwatchTheme; palette: string };

// SwatchFace previews a palette and mode; it can also lead a MenuItem.
export function SwatchFace({ theme, palette, className, ...rest }: SwatchFaceProps) {
  return <span {...rest} className={cx("ui-swatch-face", className)} data-theme={theme} data-palette={palette} aria-hidden="true" />;
}
