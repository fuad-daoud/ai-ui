# ai-ui v0.3.1: table options

Date: 2026-11-11
Status: approved by Fuad, 2026-11-11 ("go ahead", after v0.3.0 shipped and v0.3.1 was named as the
next step). Merge, tag and deploy wait for his word.

## 1. Purpose

Step 1b of the one-library rollout (v0.3 spec §1). Money and career both keep their own tables
because `.ui-table` can't draw what they need. The 2026-11-11 sizing found four needs they share:

| Need | money | career |
|---|---|---|
| No frame: the table sits on the page or in a card | every table | every table in a section card |
| A quiet header row: no fill, small grey text | 11px uppercase, `--ink-3` | 12px, `--ink-3` |
| A header that stays put while a bounded table scrolls | the ledger | `.col-scroll` tables |
| Rows that stack into cards on a phone | Admin, below 800px | all 15 tables, below 800px |

v0.3.1 adds each as an option on the table that exists. Nothing is renamed or removed.

## 2. Non-goals

- **No Go partial or React component.** Tables stay plain markup in both stacks.
- **No per-table phone layouts.** Career places each table's cells on a named grid. The library
  stacks every table the same way, and an app that wants more keeps its own placement rules.
- **No selectable or expandable rows,** no day-group rows: each is one app's.

## 3. Options

All are plain markup: attributes on `.ui-table-wrap` or `.ui-table`, and knobs.

| Option | Markup | Look |
|---|---|---|
| No frame | `data-frame="none"` on the wrap | No border, corners or fill. The first and last column sit flush with the content around the table. |
| Quiet head | `data-head="quiet"` on the table | Header cells on no fill, `--text-xs` 600 in `--ink-3`. |
| Sticky head | `data-sticky="head"` on the table | Header cells stay at the top of the wrap while it scrolls, painted `--ui-table-sticky-bg` (default `--sheet`). Bound the wrap's height with `--ui-table-max-height`. |
| Stacked on a phone | `data-stack="phone"` on the wrap | Below 800px of viewport, each row becomes a block and each cell a line with its label (§4). |

New knobs:

- On `.ui-table`: `--ui-table-head-bg` (`--band`), `--ui-table-head-fg` (`--ink-2`),
  `--ui-table-head-size` (`1em`), `--ui-table-head-case` (`none`, for `text-transform`),
  `--ui-table-head-rule` (`--rule-soft`, the line under the header), `--ui-table-hover` (a 60%
  `--band` tint), `--ui-table-sticky-bg` (`--sheet`), `--ui-table-label-width` (`8rem`, §4).
- On `.ui-table-wrap`: `--ui-table-max-height` (`none`).

Money's header is the quiet head with `--ui-table-head-case: uppercase` and
`--ui-table-head-rule: var(--rule)`.

## 4. Stacked rows

800px is the same boundary both apps use for their phone layouts and their sheets (v0.4), and it is
a viewport media query, so a table stacks exactly when the app's own phone layout starts.

Below it, inside `[data-stack="phone"]`:

- The table, its body and rows are blocks. Each row has a line under it and block padding.
- The header row is visually hidden but stays in the markup, so the column names are still there.
- A cell with `data-label` is a two-column line: the label in `--ink-3`, `--text-xs` 600, in a
  `--ui-table-label-width` column, then the value. A cell without one spans the row; give the row's
  name or title cell no label.
- A row header (`<th scope="row">`) spans the row and keeps its weight.
- Numbers (`.ui-num`) start at the value's start instead of the end.
- The wrap stops scrolling sideways, since nothing is wider than the screen.

```html
<div class="ui-table-wrap" data-stack="phone">
  <table class="ui-table">
    <thead><tr><th scope="col">Email</th><th scope="col">Role</th><th scope="col" class="ui-num">Logins</th></tr></thead>
    <tbody>
      <tr><td>ada@example.com</td><td data-label="Role">owner</td><td data-label="Logins" class="ui-num">12</td></tr>
    </tbody>
  </table>
</div>
```

**Screen readers.** Some browsers stop treating a table as a table once its rows are blocks.
`DESIGN.md` says so, and an app that needs table semantics on phones adds the ARIA table roles
(`role="table"`, `rowgroup`, `row`, `columnheader`, `cell`) to its markup.

## 5. One look changes

Row hover now applies only on a device that can hover (`@media (hover: hover)`), so a tapped row on
a phone no longer keeps its tint. Career already turns it off under a coarse pointer. The tint is
the `--ui-table-hover` knob; `transparent` turns it off.

## 6. Tests

The existing suite stays green. New, in `e2e/tables.spec.ts`, on the library fixture:

- **No frame:** the wrap has no border, radius or fill, and the first and last cells have no
  outer padding.
- **Quiet head:** no fill, `--ink-3`, 12px; `--ui-table-head-case: uppercase` and
  `--ui-table-head-rule` take effect.
- **Sticky head:** in a wrap bounded by `--ui-table-max-height`, after scrolling the wrap, the
  header cell is still at the wrap's top, painted `--ui-table-sticky-bg`.
- **Stacked, at 390px:** rows are blocks; a labelled cell shows its label through `::before`; an
  unlabelled cell has none and spans the row; the header row is visually hidden but present; the
  page does not scroll sideways; a `.ui-num` cell starts at the start.
- **Not stacked, at 1100px:** the same table is a table.
- **Hover:** a hovered row is tinted where hover exists, and not under touch emulation.

The gallery gains a stacked, unframed, quiet table, so axe and the contrast checks cover it, and
the 16 baselines change. The gallery runs at 1100px, so the baselines show it as a table; the
stacked form is measured in `tables.spec.ts`, and axe runs on it at 390px there.

## 7a. Risks

- **A stacked table loses table semantics** in some browsers. Documented, with the fix.
- **Flush edges in an unframed table** move money's first column about 10px left when it adopts
  the option. Its own knob or padding rule can keep the old inset.
