# ai-ui v0.4: menu, sheet, theme picker, ui.js

Date: 2026-11-12
Status: approved by Fuad, 2026-11-12 ("keep going do them all in the order that you recommend, go
with the recs"). The recommendations it adopts are the 2026-11-11 ones: mode × palette theming with a
light-only palette, and overlays built on the platform (popover, anchor positioning, `<dialog>`)
plus a small `ui.js`. That approval covers merge, tag and site deploy.

## 1. Purpose

Step 3 of the one-library rollout (v0.3 spec §1). Both apps hand-build the same overlays and the
same theme picker, each in two or three copies (2026-11-11 sizing, money B1–B3 and B7, career
B1, B3, B4 and B7, and Part D of both):

| Pattern | money | career |
|---|---|---|
| Menu: account, theme, row "More" | 3 menus, two keyboard models, JS-positioned | theme, account, mail row menu, admin `details.more` |
| Bottom sheet + scrim | account sheet, home theme/account sheets | theme, account, editor, ledger facts, gate Details |
| Drawer from the side | none | mail reader |
| Theme picker | swatch row (`aria-pressed`), menu rows (`menuitemradio`) | menu rows, swatch row, home copy |
| Theme state | own script, five fixed themes | own script, five fixed themes + rose |

v0.4 gives each a library part and moves the theme to mode × palette with everything the apps said
`theme.js` lacked: a change event, pressed state on the picker, a palette that has no dark mode,
and swatch faces that preview a palette that isn't applied.

## 2. Non-goals

- **No Go partials.** Menu, sheet and swatches are markup Go writes from `DESIGN.md`, like the
  dialog; React has components. Parity goldens pin the markup.
- **No toasts, tooltips, tabs, chips, segmented controls.** v0.5 takes the page parts.
- **No docked columns.** Career's editor inspector and ledger facts become columns at desktop width;
  that layout stays the app's. The sheet here is modal.
- **No `?theme=` URL override, no storage-key migration in the library.** `DESIGN.md` gives the
  six-line migration an app runs before `theme.js`.
- **No polyfill for `command`/`commandfor` or popover.** Both ship in every current engine.

## 3. Theming

### 3.1 Palette and mode on any element

`[data-palette="…"]` and `[data-theme="light|dark|system"]` now apply on any element, not just
`<html>`. That is what lets a swatch face show mono dark inside a blue light page, and it lets an
app theme one region.

- The colour tokens move to `:root, [data-palette="blue"]`; mono's block is `[data-palette="mono"]`,
  after it. Type, space, radius and motion tokens stay on `:root`.
- `[data-theme="light"]` sets `color-scheme: light`, `"dark"` dark, and `"system"` `light dark`.
- Custom properties inherit, so an element with a palette changes the tokens for everything inside
  it; it paints with them where its own CSS uses them. An app that overrides blue on `:root` writes
  `:root, [data-palette="blue"]` to reach blue swatch faces too.

Selectors keep the specificity of one attribute (0,1,0); the library's own CSS is layered, so an
app's unlayered rules still win.

### 3.2 A light-only palette

A palette with no dark values sets `color-scheme: light` in its own block:

```css
[data-palette="rose"] { color-scheme: light; --paper: …; }
```

The app's rule is unlayered and beats the library's `[data-theme="dark"]`, so rose stays light
whatever the mode. The picker offers it once.

### 3.3 `theme.js`

Stays one blocking script in `<head>`. New:

- **`aiui:themechange`**, a `CustomEvent` on `document` whose `detail` is `get()`, fired after every
  `set()` and when the OS flips light/dark while the mode follows the system.
- **Pressed state.** Every element carrying `data-ui-set-theme` or `data-ui-set-palette` gets
  `aria-pressed="true|false"`, or `aria-checked` when its role is `menuitemradio`, `menuitemcheckbox`
  or `radio`. It matches when each attribute it carries equals the current value: an empty
  `data-ui-set-theme` means `system`; an empty `data-ui-set-palette` means the page's default (the
  server's `data-palette`, else `blue`). Synced on `DOMContentLoaded` and after every change.
- **`aiui.theme.sync(root?)`** re-marks the elements under `root` (default `document`), for markup
  added later (a menu built on demand, a React render).

## 4. Menu: `.ui-menu`

A popover (`popover` attribute, auto). The opener is any button with `popovertarget`; the browser
then gives light dismiss, Escape, focus return and `aria-expanded`, and makes the opener the
menu's anchor.

```html
<button class="ui-btn" type="button" popovertarget="acct" aria-haspopup="menu">Account</button>
<div class="ui-menu" id="acct" popover role="menu" aria-label="Account">
  <p class="ui-menu-label" role="none">grace@example.com</p>
  <a class="ui-menu-item" role="menuitem" href="/account/">Account</a>
  <hr class="ui-menu-sep">
  <form method="post" action="/logout" role="none"><button class="ui-menu-item" role="menuitem">Sign out</button></form>
  <button class="ui-menu-item" role="menuitem" type="button" data-variant="danger">Delete</button>
</div>
```

| Part | What it is |
|---|---|
| `.ui-menu-item` | A row: `<button>` or `<a>`, `role="menuitem"`. `data-variant="danger"` paints it `--bad`. `role="menuitemradio"` with `aria-checked="true"` draws a check at the end. A leading `svg` or `.ui-swatch-face` is 1em. |
| `.ui-menu-label` | A caption or identity row: small, `--ink-3`, one line with an ellipsis. Not focusable. |
| `.ui-menu-sep` | A hairline (`<hr>`, whose role is separator). |
| `.ui-menu-head`, `.ui-menu-title`, `.ui-menu-x` | A head shown only when the menu is a sheet (§4.2). The × is `<button class="ui-menu-x" role="menuitem" popovertarget="acct" popovertargetaction="hide" aria-label="Close">`. |
| `.ui-swatches` | Allowed inside a menu (§6). |

### 4.1 Place

Anchored with CSS anchor positioning to the opener: below it, its end edge on the opener's end edge
(`position-area: block-end span-inline-start`), flipping above or to the other side when there's no
room. `data-align="start"` lines up the start edges instead. Where `position-area` isn't supported,
`ui.js` places the menu the same way from the opener's box.

### 4.2 On a phone

`data-sheet="phone"`: below 800px the menu is a bottom sheet, full width, rounded on top, at most
70% of the viewport tall, its rows 44px, over a `--scrim` backdrop. The head shows. Tapping the
backdrop closes it (popover light dismiss).

### 4.3 Keys (`ui.js`)

On open, focus moves to the checked item, else the first item. Down/Up move through items and
wrap; Home/End go to the ends; Left/Right move within a swatch row. Tab closes the menu and moves on
from the opener. Activating a `menuitem` closes the menu (its link or form still goes); a
`menuitemradio` or swatch keeps it open, so a theme can be tried in place. Escape and an outside
click are the browser's.

Knobs on `.ui-menu`: `--ui-menu-width` (`16rem`), `--ui-menu-bg` (`--sheet`), `--ui-menu-border`
(`--rule`), `--ui-menu-radius` (`--radius-md`), `--ui-menu-shadow` (`0 8px 24px var(--shadow)`),
`--ui-menu-item-height` (`2.25rem`; 34px compact; 44px on a coarse pointer and as a sheet),
`--ui-menu-hover` (`--band`). A menu keeps its shadow in compact: it floats over content.

## 5. Sheet: `.ui-sheet`

A modal `<dialog>` docked to an edge: the bottom by default, `data-side="end"` for a drawer from
the inline end. Open it like a dialog (`command="show-modal" commandfor`); the browser makes the
page inert, traps focus, closes on Escape and returns focus. `closedby="any"` closes it on a
backdrop tap too (`ui.js` adds that where the attribute isn't supported).

```html
<dialog class="ui-sheet" id="facts" aria-labelledby="facts-title" closedby="any">
  <header class="ui-sheet-head">
    <h2 class="ui-sheet-title" id="facts-title">Facts</h2>
    <button class="ui-sheet-x" type="button" command="close" commandfor="facts" aria-label="Close">×</button>
  </header>
  <div class="ui-sheet-body">…</div>
</dialog>
```

Bottom: full width, `--ui-sheet-max-height` (`70dvh`), top corners rounded. End: full height,
`--ui-sheet-width` (`28rem`, never wider than the viewport), start corners rounded. One shadow,
`0 0 24px var(--shadow)`, serves both sides, so compact can turn it off with one knob. The head is
3rem with a hairline; the body scrolls with `overscroll-behavior: contain`. A modal sheet
(`:modal`) slides in over `--dur` unless reduced motion is asked for; a sheet drawn in place
(`open`, not modal) doesn't move.

Knobs: `--ui-sheet-bg` (`--sheet`), `--ui-sheet-border` (`--rule`), `--ui-sheet-radius`
(`--radius-lg`), `--ui-sheet-shadow`, `--ui-sheet-pad` (`--space-4`), `--ui-sheet-max-height`,
`--ui-sheet-width`. Flat in compact, like dialogs and cards.

## 6. Theme picker: `.ui-swatches`, `.ui-swatch`, `.ui-swatch-face`

```html
<div class="ui-swatches" role="group" aria-label="Theme">
  <button class="ui-swatch" type="button" data-ui-set-theme="system" data-ui-set-palette="blue" aria-label="System">
    <span class="ui-swatch-face" data-theme="system" data-palette="blue" aria-hidden="true"></span></button>
  <button class="ui-swatch" type="button" data-ui-set-theme="light" data-ui-set-palette="blue" aria-label="Blue">
    <span class="ui-swatch-face" data-theme="light" data-palette="blue" aria-hidden="true"></span></button>
  <button class="ui-swatch" type="button" data-ui-set-theme="dark" data-ui-set-palette="mono" aria-label="Black and white dark">
    <span class="ui-swatch-face" data-theme="dark" data-palette="mono" aria-hidden="true"></span></button>
</div>
```

Each swatch names its mode and palette explicitly, so it matches whatever the page's default is.

- A **swatch** is a button carrying the choice (`data-ui-set-*`, §3.3); `theme.js` marks the
  current one pressed, drawn with a 2px `--ink` ring. Swatches share the row equally, 2rem tall
  (2.5rem on a coarse pointer).
- A **face** previews its palette and mode from the tokens (§3.1): `--paper` ground, a `--primary`
  corner, a `--rule` edge. `data-theme="system"` splits it diagonally, light over dark.
- In a menu, a face can lead a `menuitemradio` row instead: name and check, the face as its icon.
- Left/Right/Home/End move between swatches (`ui.js`).

## 7. `ui.js`

One deferred script, `<script src="{{href "ui.js"}}" defer></script>`, for the menu's keys and
place (§4.3, §4.1), swatch arrows (§6), and `closedby="any"` where unsupported (§5). It listens
on `document`, so markup added later needs nothing, and it does nothing on a page without these
parts. The menu and sheet still open, close and dismiss without it. React apps import it once:
`import "ai-ui/ui.js"`.

## 8. React

`Menu` (`id`, `label`, `sheet="phone"`, `align="start"`, `title` for the sheet head, `closeLabel`),
`MenuItem` (`variant="danger"`; `checked` makes it a `menuitemradio`; `icon`),
`MenuLink` (the same, as a link), `MenuLabel`, `MenuSeparator`; `Sheet` (`id`, `title`, `side="end"`, `closeLabel`, `closeButton`,
`dismissible` → `closedby="any"`); `Swatches` (`label`), `Swatch` (`theme`, `palette`, `label`), `SwatchFace` (`theme`, `palette`).
`Swatch` leaves `aria-pressed` to `theme.js`, and calls `aiui.theme.sync` after it mounts.
`Button` already passes `popoverTarget`.

## 9. Tests

- Parity goldens for every React component, written from `DESIGN.md`'s markup.
- `theme.js` (vitest, jsdom): the event on `set()` and on an OS flip; pressed and checked marks;
  empty values meaning system and the default palette; `sync()`.
- Browser (Playwright on contabo):
  - menu: under its opener and end-aligned; flips above near the bottom; `data-align="start"`;
    first or checked item focused on open; arrows, Home/End, wrap; Tab closes; a menuitem closes
    it and a radio doesn't; Escape returns focus; a phone sheet with its head and scrim; axe.
  - sheet: bottom and end placement and size; inert page; backdrop tap closes with `closedby`;
    no motion under reduced motion; flat in compact.
  - picker: faces paint their own palette and mode inside another one; the system face is split;
    a click sets the theme, marks it pressed and fires the event; a light-only app palette stays
    light under `data-theme="dark"`; arrows move between swatches.
- Gallery: a menu and a sheet opener, a picker, and a menu and a sheet drawn in place on every
  page; 16 baselines change.
- Site: Menu, Sheet and Theme picker sections on Components with live demos (the picker's demo
  themes only its own box: the site stays dark), and the three in the home page's pile, whose
  swatches theme the pile. The site serves `ui.js`.

## 10. Breaking changes

None by the CHANGELOG's rule (no name removed or renamed). One look can change: an element other
than `<html>` that already carried `data-theme` or `data-palette` now takes that mode or palette.
