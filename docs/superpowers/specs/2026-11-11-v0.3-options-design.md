# ai-ui v0.3: options on the components that exist

Date: 2026-11-11
Status: approved by Fuad, 2026-11-11 ("write all the sections, plans, and start building, merge,
and release, and deploy")

## 1. Purpose

Money and career are both on ai-ui, but each still works around the library in the same places.
The 2026-11-11 sizing (https://claude.ai/artifact/UPKBihsonSFYkFpEWttGPL) read both apps and
listed every override of a `ui-*` class and every local knob. v0.3 turns the overrides that both
apps share into documented options, so the apps can delete overrides instead of adding more.

This is the first of five steps toward both apps taking every generic component from ai-ui:

1. **v0.3:** options on existing components (this spec). Tables follow as v0.3.1.
2. Career adopts pill, card, dialog and disclosure, then tables.
3. v0.4: menu, sheet and scrim, theme picker, `ui.js`, `theme.js` upgrades.
4. v0.5: page head, section head, stat tiles, filter chip, empty state, meter, selected row.
5. Money adopts everything and removes `compat.css`.

**Fuad's decisions (2026-11-11):**

- Theming moves both apps to mode × palette, with a light-only flag on a palette (v0.4).
- Overlays build on the platform (popover, anchor positioning, `<dialog>`) plus a small `ui.js` (v0.4).
- Compact density draws no shadow on cards and dialogs. Disabled controls change colour instead of
  fading, at every density. Money accepts compact's 1px differences from its own register.
- Tables and disclosures move into the library. Tables ship as v0.3.1, just before career moves
  its tables.

## 2. Non-goals

- **Nothing is renamed or removed.** Every change is additive, except the two looks §6 changes.
- **No new components.** The menu, sheet and the rest are v0.4 and v0.5.
- **No table options.** The stacked phone mode, an unframed table and head knobs are v0.3.1.
- **Nothing only one app needs.** Money's edge-only callout and its error shown on `:user-invalid`
  stay money's, by the rule that the library takes what more than one app needs.
- **No migration.** Moving either app is separate work with its own plans.

## 3. How an option is written

The contract already has two kinds of option, and v0.3 keeps to them:

- **A look you pick per element is a `data-*` attribute**, like `data-variant` and `data-size`. A
  default is never written, and an unknown value renders the default.
- **A value you tune is a `--ui-*` knob**, set on the element in the app's own unlayered CSS.

New attribute names: `data-tone`, `data-shape`, `data-width`, `data-dot`, `data-marker`. Each Go
partial and React component that renders the element takes the option as an argument or prop with
the same name, as `Variant`/`variant` do today.

`data-tone="outline"` is career's existing local name for its outlined danger button, so career's
12 sites become library markup unchanged.

## 4. Controls

### Button

| Option | Markup | Go | React | Look |
|---|---|---|---|---|
| Outline | `data-tone="outline"` | `Tone "outline"` | `tone="outline"` | Sheet fill, `--rule` border, `--band` on hover. Text in `--primary` for a primary button and `--bad` for danger. Secondary and ghost don't change. |
| Square | `data-shape="square"` | `Shape "square"` | `shape="square"` | Width equals `--ui-btn-height`, no inline padding. For an icon-only button. |
| Full width | `data-width="full"` | `Width "full"` | `width="full"` | 100% wide; the label wraps, balanced, with `--space-1` block padding. |
| Icon | an `<svg>` before the label | `Icon` (`template.HTML`) | `icon` (a node) | Rendered first, inside the button. |

A square button needs an icon and a label. The label becomes its `aria-label`, and the icon is its
only content. In Go, a square button without `Icon` is an error, as a button without `Label` is;
`Icon` is written as given, so it must be `template.HTML` from the app's own templates or code.
In React, a square button's children must be text, and that text becomes the `aria-label`.

The selectors that set the outline's text colour use `:where()` for the variant, so they weigh the
same as a variant rule and the disabled rule (§6) after them still wins.

### Inputs, selects and textareas

| Option | Markup | Go (`ui.field`) | React (`Field`) |
|---|---|---|---|
| Size | `data-size="sm"` or `"lg"` on the control | `Size` | `size` |
| Leading icon | `.ui-input-group` around an `.ui-input-icon` and the input | `Icon` (input only) | `icon` (input only) |

Sizes match the button of the same size at each density:

| | Default density | Compact |
|---|---|---|
| `sm` | 32px, `--text-sm`, `--space-2` inline padding | 28px |
| `lg` | 48px, 16px text, `--space-4` inline padding | 44px |

On a select, the size changes only the start padding, so the drawn chevron keeps its room.
React's `size` replaces the native numeric `size` attribute, which a full-width control never
uses; this keeps one name for size across the library.

```html
<div class="ui-input-group">
  <svg class="ui-input-icon" aria-hidden="true">…</svg>
  <input class="ui-input" type="search" aria-label="Search merchants">
</div>
```

The icon is 1rem, in `--ink-3`, centred on the control's height, and takes no pointer events.
The input's start padding grows to clear it. Knob on the group: `--ui-input-icon-inset` (default
`--space-3`; `--space-2` around a small input, `--space-4` around a large one).

**Widths.** `--ui-input-width` (default 100%) sets a control's width. On a child of
`.ui-form-row`, `--ui-row-grow` (default 1) and `--ui-row-basis` (default 14rem) set its flex grow
and basis, so one row can hold a wide field next to a narrow one.

### Touch sizes in compact density

Under `(pointer: coarse)`, compact controls grow to the finger sizes both apps already use:

| | Button | Input, select |
|---|---|---|
| default | 40px | 40px |
| `sm` | 34px | 34px |
| `lg` | 44px | 44px |

The default density is unchanged: its controls are already 40px.

## 5. Containers

### Card

New knobs `--ui-card-shadow` (default `0 1px 2px var(--shadow)`) and `--ui-card-border` (default
`--rule-soft`). **In compact density the shadow is `none`.**

### Dialog

- New knobs `--ui-dialog-shadow` (the current two-layer shadow) and `--ui-dialog-border` (default
  `--rule-soft`). **In compact density the shadow is `none`;** the scrim still sets the dialog off.
- **Eyebrow:** a `<p class="ui-dialog-eyebrow">` as the dialog's first child, above the head. It is
  `--text-xs`, 600, uppercase with 0.06em tracking, coloured by the `--ui-dialog-eyebrow-fg` knob
  (default `--ink-3`). An app that wants a red "Can't be undone" sets the knob to `--bad`.
- **The × is optional.** In Go, leave the button out of the markup. In React, `closeButton={false}`
  leaves it out. A dialog without one must still close: a Cancel button with
  `command="close" commandfor="<id>"` does that.
- React's `Dialog` gains `eyebrow` (a node).
- **Shown without script:** a `<dialog open>` already lays out as a dialog, in the flow, without a
  backdrop. `DESIGN.md` says so, for a confirm that has to work with script off.

### Pill

| Option | Markup | Go | React | Look |
|---|---|---|---|---|
| Dot | `data-dot` (no value) | `Dot true` | `dot` | A 6px dot in the pill's text colour, before the label. |
| Outline | `data-tone="outline"` | `Tone "outline"` | `tone="outline"` | No fill; the border takes the text colour, or `--rule-field` on a neutral pill. |

`info` is already outlined, so the tone changes nothing on it.

### Disclosure

- `data-marker="start"` on the `<details>` moves the chevron before the summary text, pointing to
  the inline end when closed and down when open (mirrored in right-to-left text).
- New knob `--ui-disclosure-rule` (default `--rule-soft`), the line under each disclosure. Set it
  to `transparent` for none.

## 6. The two looks that change

Both are listed first in the changelog.

1. **Disabled buttons, at every density,** draw a `--band` fill, `--ink-3` text and a `--rule`
   border, at full opacity, instead of `opacity: 0.5`. A ghost button keeps no fill and no border.
   Hover changes nothing. `pointer-events: none` stays only on a disabled link (`aria-disabled`),
   which must not navigate; a disabled `<button>` already ignores clicks and now shows the
   not-allowed cursor. Fields and checks already use colour, so they don't change.
2. **Compact cards and dialogs have no shadow.** Their border stays.

## 7. Tests

The existing suite stays green: Go, vet, gofmt, `tsc`, vitest, the browser tests, axe and the
contrast checks. New:

- **Parity fixtures** for each new argument: the button's tone, shape and width; the pill's dot and
  tone; the field's size and icon; the dialog's eyebrow and missing × (React only, golden by hand,
  as the dialog is today). Icon fixtures use a text glyph, which both sides render alike. In Go,
  `templates_test.go` also checks that a `template.HTML` icon goes in as markup and a string is
  escaped.
- **Errors:** a square button without `Icon` (Go) or with non-text children (React).
- **Browser, measured (`e2e/options.spec.ts`)** on the library fixture, at both densities:
  - a small and a large input and select are as tall as the button of that size;
  - a square button is as wide as it is tall;
  - a full-width button fills its row and wraps a long label;
  - an outline danger button's text is `--bad` and its fill `--sheet`;
  - a disabled button's opacity is 1 and its fill `--band`, also when it is outlined or danger;
  - under touch emulation, compact controls are 40, 34 and 44px, and default ones don't change;
  - the input icon sits inside the input and the text starts after it;
  - `--ui-row-basis` and `--ui-input-width` take effect;
  - a compact card and dialog have no shadow, and a default one does;
  - the eyebrow sits above the title, and a dialog without × still lays out;
  - a dotted pill draws its dot in its text colour; an outline pill has no fill;
  - a start-marker disclosure draws its chevron before the text and turns it when opened.
- **Gallery:** each section shows the new options, so the screenshot, contrast and axe runs cover
  them in every palette, mode and density. All 16 gallery baselines change, by the new content and
  by §6.
- **No effect without the attribute** keeps passing: every new compact rule, the touch sizes
  included, sits under `[data-density="compact"]`.
- `classes_test.go` gains `ui-dialog-eyebrow`, `ui-input-group` and `ui-input-icon`.

## 9. Release

Built through relevo on `feat/v0.3`, as v0.2 was: the plans carry exact code taken from a trial
tree, and the chain's head must equal that tree. Then:

1. PR to `main`; CI must pass. Merge with a merge commit.
2. Tag `v0.3.0` on the merge commit; CI checks it matches `package.json`.
3. `go list -m github.com/fuad-daoud/ai-ui@v0.3.0` resolves.
4. Redeploy the site, which then shows 0.3.0.

Neither app moves in this release. Both keep their pinned versions until their own plans.

## 10. Risks

- **The disabled change shows in both apps when they upgrade.** Money already draws this look by
  override; career's disabled buttons change from faded to grey. Each app's before-and-after run
  shows it.
- **Compact cards and dialogs lose a shadow.** Money's sign-in card already removes it by hand.
  Career uses neither component yet.
- **Touch sizes grow compact controls on phones and tablets.** Career sets the same sizes by
  override today, and money's home sets its own. An app that wants smaller touch targets sets the
  knobs, as before.
- **`size` on React's `Field` hides the native attribute.** Documented; no known use.
