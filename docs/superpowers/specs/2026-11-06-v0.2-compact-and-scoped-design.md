# ai-ui v0.2: compact density and a scoped stylesheet

Date: 2026-11-06
Status: approved by Fuad, 2026-11-06

## 1. Purpose

Career can't move onto ai-ui as v0.1 stands, for two reasons:

- **Size.** ai-ui's default is 40px controls at 16px. Career and money both run 32px controls with
  4px corners, because they are working tools.
- **The résumé preview.** It has to match the PDF, and it loads the same stylesheet as the nav
  drawn on top of it. `ui.css` carries a reset and base rules that apply to every element, so
  linking it from the nav would restyle the résumé.

v0.2 adds a compact density and a second stylesheet that styles library markup only. It removes
nothing and renames nothing.

**Fuad's decisions (2026-11-06):**

- Career takes ai-ui's look at compact density, not its own look through overrides.
- Only controls and messages move in career. Its tables stay its own, as money's did.
- Plan and build only as far as career's sign-in pages, then decide on the rest.

## 2. Non-goals

- **The default look doesn't change,** apart from the one field fix in §5.
- **No new components.** Career's later stages may need some, and they get their own releases.
- **No change to button defaults.** A compact app still writes `data-variant="secondary"` for its
  outlined button, as money does.
- **Tables gain no phone stacking.** Career and money keep their own tables.
- **No migration here.** Moving career and moving money up from v0.1.0 are separate work. Money
  isn't required to take v0.2.
- **No React density prop.** Density is an attribute on an element, which React already sets.

## 3. Compact density

### Contract

```html
<html data-density="compact">          <!-- the whole page -->
<div data-density="compact">…</div>    <!-- one part of a page -->
```

Inside it, every library component is compact. The default stays the default: no attribute means
today's look, and `data-density` has no other value in v0.2. Nesting a default region inside a
compact one isn't supported.

| | Default | Compact |
|---|---|---|
| Button | 40px, 16px text | 32px, 14px text, 12px side padding |
| Button `data-size="sm"` | 32px, 14px | 28px, 13px, 10px side padding |
| Button `data-size="lg"` | 48px, 18px | 44px, 16px, 20px side padding |
| Input, select | 40px (see §5), 16px | 32px, 14px |
| Textarea | 80px, 16px | 80px, 14px |
| Field label, hint, error | 14px | 13px |
| Field gap | 8px | 4px |
| Controls, callout, table wrap | 6px corners | 4px corners |
| Card, dialog | 10px corners | 8px corners |
| Pill | fully round | 4px corners |
| Table text | 14px | 14px |
| Body text (`data-density` on the page) | 16px | 14px |

Heading sizes and the spacing tokens don't change. Compact is about controls and body text, and
it stays a single switch: density and corners move together, because both apps that need it want
both.

### How it works

One new file, `css/components/density.css`, in the `ui.components` layer. It changes no existing
rule, so a page without the attribute renders exactly as before.

Inside the attribute it redefines `--text-md`, `--text-sm`, `--radius-md` and `--radius-lg`, then
sets the component knobs those tokens don't reach: the button and field heights, button padding,
the field gap, and the pill's corner.

- **Compact rules win on specificity,** not order: `[data-density="compact"] .ui-btn[data-size="sm"]`
  beats `.ui-btn[data-size="sm"]`, so the source order within the layer doesn't matter.
- **App overrides still win.** An unlayered app rule beats all of this, as the override model
  already promises.
- **`font-size` is set only on a non-root element.** Setting it on `:root` also shrinks `rem`,
  and 32px buttons came out at 28px when the spike did that. On the page root, `body` picks up the
  redefined `--text-md` through the rule it already has.

## 4. The scoped stylesheet

### Contract

A second published asset, `ui-scoped.css`, served and versioned like `ui.css`:

- Go: `ui.Href("ui-scoped.css")`
- npm: `ai-ui/ui-scoped.css`

A page loads one or the other. With `ui-scoped.css`:

- **Library markup looks as it does under `ui.css`,** including focus rings and headings inside
  library components.
- **Everything outside library markup is untouched.** Library markup means an element with a
  `ui-*` class and everything inside it.

What the page gives up, by design:

- **No page-level styling.** `body` gets no background, font or colour, and links outside library
  markup get no colour.
- **Library markup inherits its font from around it,** so the surrounding app sets `font-family`.
- **Compact goes on a container.** With no `body` rule, the page-level form doesn't set body text.
  Career's nav would carry `data-density="compact"` itself.
- **Tokens still apply to `:root`,** including `color-scheme: light dark`. A page that sets no
  `color-scheme` of its own will follow the system's dark mode for its default colours. The
  preview sets its own through `workbench.css`, so it isn't affected.

### How it works

`internal/build` generates it from the same sources as `ui.css`, so the two can't drift:

- **`reset.css` and `base.css`:** each selector gains
  `:where([class^="ui-"], [class*=" ui-"], [class^="ui-"] *, [class*=" ui-"] *)`, which adds no
  specificity. Rules on `html` and `body` are dropped.
- **Tokens, components and utilities:** copied unchanged, in the same layers.
- **Anything the generator can't rewrite fails the build,** so a new reset rule can't leak onto
  an app's page without someone noticing.

The file is about 3.4 KB larger than `ui.css`, 21.3 KB against 17.9 KB, and only pages that link it
pay for that.

## 5. One fix: fields match buttons

At the default size, inputs and selects render taller than buttons beside them: 43.6px against
40px, because their padding and line height add up to more than their minimum height. v0.2 removes
their block padding so they are 40px, like a button. Textareas keep theirs.

This is the one visible change at default density. It's a fix rather than a rename, so it isn't
breaking under spec §9, but `CHANGELOG.md` lists it first so an app notices it when upgrading.
Compact needs the same thing, and fixing it in the base rule means compact doesn't override it.

## 6. What the spike measured

A throwaway copy of the design, in Chromium, with invented résumé text. The plan reproduces these
results as tests.

| Check | Result |
|---|---|
| Career's real résumé CSS plus `workbench.css`, adding `ui-scoped.css` | Pixel-identical, light and dark. 0 computed differences. |
| The same, adding `ui.css` | Pixels change. 347 computed differences. |
| Library markup under `ui.css` and `ui-scoped.css` | Same, with one exception: an unclassed `<p>` in the test page, and the pills it passes `overflow-wrap` and `text-wrap` to |
| Focus ring under each file | Same: 2px solid, 2px offset |
| Density file loaded, no attribute | 0 computed differences from `ui.css` |
| Compact on the page and on a container | Buttons 32, 28 and 44px; inputs and selects 32px; 14px text; 4px corners |

The spike's corner tokens produced a 4px table wrap and 8px cards and dialogs, as §3 states. Career's
`.pill` is 22px and compact gives 22.8px. I'm leaving that, because career's stage 2 is where it can
be judged on real pages.

The plan's trial then measured the field fix at the default size: inputs and selects are 40px beside
a 40px button.

## 7. Tests

The existing suite stays green, including the contrast and axe runs. New:

- **Compact sizes:** a Playwright test asserts the §3 table, with the attribute on the page and on
  a container, and includes a guard that `rem` stays 16px.
- **No effect without the attribute:** computed styles across the gallery match with and without
  `density.css`.
- **Gallery:** gains a compact section, so the screenshot, contrast and axe runs all cover it.
- **Scoped, résumé side:** a fixture page with bare `h1`, `p`, `ul`, `table`, `a` and `img` and its
  own CSS. Adding `ui-scoped.css` changes no computed style on them, and the same test confirms
  that adding `ui.css` does, so a broken fixture can't pass.
- **Scoped, library side:** computed styles on every component match under the two files.
- **Generator:** every selector from the reset and base carries the `:where()` scope; an
  unrecognised construct fails the build; `dist/ui-scoped.css` is fresh, like `dist/ui.css`.
- **Handler:** serves `ui-scoped.css` with the same caching as `ui.css`.
- **Field fix:** an input, a select and a button in one row have the same height at both densities.

`classes_test.go` and `DESIGN.md` gain the new attribute. `DESIGN.md` gains a section on each
feature, and its adoption section says when to choose `ui-scoped.css`.

## 8. Release

v0.2.0: one tag, as usual, with the version in `package.json` matching it. Nothing is renamed or
removed. Built through relevo on a branch, merged by PR once CI and the planner's checks pass.

Career's plans for its stages 1 and 2 pin v0.2.0, and they're written after this ships. Their own
checks stand: the preview must still match the PDF, this time on career's real pages.

## 9. Risks

- **The scope selector misses a case.** An app's own class that starts `ui-` would count as library
  markup. Apps shouldn't use the prefix, and `DESIGN.md` will say so.
- **Compact reads wrong on real pages.** Everything so far is a sample panel. Stage 2 of career is
  the first real look, and since only an additive release has shipped by then, stopping there
  costs little.
- **Field fix surprises an app.** Only money uses ai-ui today, it's pinned to v0.1.0, and its rules
  state its own field sizes. Its before-and-after run would show any change when it upgrades.
